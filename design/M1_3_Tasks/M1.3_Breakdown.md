## 1. The one thing M1.3 must prove

M1.2 proved the cost axis is now *visceral* (2× run length, real hazard deaths, three-way outcomes) but the playtest
left it **half-tuned and half-tested**: the most-fun config isn't the default, huge rooms are *empty* (one hazard, long
boring hallways), the depth readout is wrong, and two oppositions (R3/BUG5, R4-lost) were silently config-disabled so
they never actually ran. **M1.3 makes the fun config the default, fills the big rooms with distributed danger, fixes the
readout, and guarantees every enabled opposition actually fires — then re-gates for a possible "go."**

## 2. Scope guardrails (what M1.3 is and is NOT)

- **Greybox + configurable-not-balanced**, exactly as M1.1/M1.2. Every new lever is a swept `RunConfig` knob; the value
  is the Director's to sweep, not ours to finalize.
- **The all-off `RunConfig` default stays the permanent baseline control** (determinism fp=`e943ac9c8bc1`,
  telemetry comparability with M1.0/M1.1/M1.2). F1's "fun defaults" ship as a **separate named play-preset the game boots
  into**, NOT by changing the code-level all-off defaults. This is the load-bearing M1.3 contract.
- **NOT** new bands, new real art, a generator rewrite, or new gameplay systems. Density = more of the existing hazard;
  hallway-length + per-room density are knobs on the existing generator/placer.
- `run_ended` arity stays locked; telemetry stays schema v1 (additive `data` fields only); new EventBus signals are
  pre-declared the M1.1 way (owner declares on `main` before any parallel wave; the rest subscribe).
- Config-marked telemetry continues; the re-gate compares M1.3 cohorts to the M1.0/M1.1/M1.2 baselines on the same metrics.

- **Wave 1 — Foundation & correctness** (parallel worktrees, ownership-split): **J1** (preset + `run_config`/CFG size range) ∥ **BUG6** (hazard debounce + config-trap guard) ∥ **J5** (depth HUD) ∥ **DLV1** (itch infra — disjoint from code).

- **Wave 2 — Density & spatial** (after Wave 1 on `main`): **J2** (enemy spread) ∥ **J4** (hallway length + corridor telemetry) — both may touch `band_generator.gd`/`junk_placer.gd`/`main_game.gd` hazard-spawn; **assign single-writer ownership per file at brief time**. **J3** (per-room density) pairs with J2 — sequence or co-own the hazard-spawn seam (design them as one seam in Phase 2).
- **Wave 3 — Re-gate** (sequential): RG1 build+verify → **Director playtest** (auto-published to itch via DLV1) → RG2 analysis → RG3 verdict.

## 6. Cross-cutting contracts (carried from M1.1/M1.2)

- **Configurable knob + config-marked telemetry**, all-off default reproduces the prior baseline as the permanent control.
  Every new knob joins `RunConfig.to_flat_dict()` + CFG `has_full_coverage()` (the build-time coverage assertion) +, where
  spatial, the `fingerprint(seed+config)` determinism key. Update `tests/test_run_config.gd`/`test_config_menu.gd` knob counts.
- **The default play-preset is a separate artifact** (a `.tres` or named CFG default), NOT the code-level all-off default.
  The all-off control must stay byte-identical (fp=`e943ac9c8bc1`); a determinism test asserts it.
- **Single-writer-per-`.gd`-file** within a wave; **pre-declare any new EventBus signal on `main`** before a parallel wave
  (J4's corridor-time telemetry and BUG6's config-trap warning may want one — decide in Phase 2; if so, pre-declare).
- **Parallel agents in `isolation: worktree`**; verify each branch's topology before merge (the qa-agent `git switch`
  leak — see the orchestrator's memory); push `main` after every merge; mirror task status to the board; run the wave
  close-out deviation sweep (Director dispositions) after every wave.
