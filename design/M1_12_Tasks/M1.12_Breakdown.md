> used — each opened ahead of the prior gate). M1.11's Director playtest → UG2 → UG3 stay
> pending and non-blocking. The Director's directive: **"Implement the scaling recommendations
> from the M1.11 systems-state report (`design/report-09072026.docx`) — all of them except the
> first (the CSV-driven item catalog, R1), which is deferred to a future iteration."**
>
> **Source (the design input — read before any task):**
> - `design/report-09072026.docx` — "THE FAR YARD — Game Systems State Report" (9 July 2026,
>   commit line `53d9fb9`), assembled from six parallel subsystem surveys over the M1.11 working
>   tree. **§10 "Scaling Recommendations"** is the task source. This version implements **R2–R10**;
>   **R1 (CSV item catalog + importer) is Director-deferred** to a future iteration.
> - The report's finding that motivates the whole version: *"Known, deliberate debt is
>   accumulating"* — and that after three content-scaling iterations (M1.9→M1.11 proved
>   "new content = data"), the seams that made that possible now carry duplication, a god-object,
>   dual-emit signals, and a fragile index-aligned authoring surface. **M1.12 pays that debt down
>   before M2 (crafting/upgrades/instability) lands on top of it.**

**The one thing this version must prove:** *the scaling debt can be retired without moving the
game.* M1.9–M1.11 proved the seams SCALE (content = data, declining marginal cost). M1.12 proves
they can be CLEANED — every recommendation lands as a **behavior-preserving refactor or a pure
deletion**, with the game bit-for-bit unchanged where a fingerprint pins it and green across the
full existing suite everywhere else. This is the inverse of the last three versions' measure: not
"how few lines does new content cost" but **"how much debt comes OUT" — net lines deleted, copies
collapsed, coupling reduced, and one-way-to-do-each-thing restored** — with a hard regression
floor: nothing the player can see or feel changes. The measure of success is the **debt ledger**
(each task's worklog records net LOC removed + the duplication/coupling retired) plus a **green
regression gate** (all four control fingerprints byte-identical, full suite green, the build still
runs on itch). If M1.12 succeeds, M2 builds on clean seams; if it can't be done without moving the
game, that itself is the finding UG3 judges.

## Scope guardrails

- **R2–R10 ONLY — R1 (CSV catalog) is explicitly out.** The CSV-driven item catalog + importer is
  the report's highest-leverage item but is Director-deferred to a future iteration; M1.12 does not
  author a CSV pipeline. **However R2 (kill the index-aligned weights) is IN** — the report frames
  it as "even before/without R1," a standalone small fix that also de-risks the future R1. Doing R2
  now makes the deferred R1 strictly simpler.
- **Behavior-preserving is the master contract.** Every task is a refactor or deletion that leaves
  observable behavior unchanged. The four permanent controls stay byte-identical at every wave
  boundary: the all-off `RunConfig` **layout** fingerprint **`e943ac9c8bc1`**, and the
  `band_greybox`, `band_two`, `band_three` **layout** fingerprints. The full existing test suite
  (~78 scripts) stays green after every merge. A refactor that cannot preserve a fingerprint is a
  **flagged deviation with a designated re-pin + equivalence proof**, never a silent drift (see the
  V3 exception below — the ONE sanctioned behavioral change, and it does not touch a layout fp).
- **The ONE sanctioned behavioral change (V3 / R4):** migrating band_greybox's legacy hazard lane
  onto the deck lane **necessarily changes the hazard-SPAWN sequence** of the greybox play preset
  (a deck spender draws differently than the K5 fair-share machine). This does **not** touch any
  layout fingerprint (hazards are OFF in the all-off `e943ac9c8bc1` control; layout fps are
  hazard-free). It DOES change hazard-spawn golden tests. V3 must (a) leave all four layout fps
  byte-identical, (b) prove behavioral **equivalence** of the new greybox deck to the old
  fair-share machine (same hazard types present; comparable counts/distribution within a stated
  tolerance; entry-safety + caps preserved), and (c) re-pin the affected hazard-spawn goldens with
  that equivalence documented. This is the version's single highest-risk task and its fp-change is
  a **Needs Director review** item (DR-3).
- **Determinism contract holds unchanged.** V6 (RNG.substream) promotes the existing salted
  sub-stream idiom into an autoload helper — it MUST reproduce every current sub-stream
  **byte-identically** (there are two live idioms today: `run_seed ^ SALT` in GameState pockets/exits
  and `hash_combine`-based `_stage_seed` in bandgen/junk_placer; the helper preserves both, or is
  proven equal per call site). Any fp move from V6 is a bug, not a deviation.
- **No save-schema change anywhere in M1.12.** Meta schema stays v4. V9's run.sav disposition
  (implement vs delete the dead path) does not bump the meta chain; if run.sav is deleted it is a
  dead-code removal, if kept it stays declared-and-unused (Director call, DR-6).
- **No new player-facing content, no new feature, no new tuning.** No new band, opposition, item,
  shop entry, or knob. RunConfig may LOSE knobs (V3 deletes the special-cased `rc.h*_*` legacy
  groups) but gains none. The config menu shrinks; it never grows.
- **Autoload count stays at six.** V4 (split GameState) splits along seams into **sub-objects owned
  by GameState** (Economy / QuotaLadder / a slimmer lifecycle core), NOT new singletons — the
  GameState facade is preserved so its ~38 dependent files are untouched (DR-4). EventBus signal
  count only shrinks (V2 retires six legacy per-type signals); it never grows.
- **Single-writer-per-`.gd`-file per wave** holds, enforced by the wave grouping below. The two
  effort-L refactors (V4 GameState split, V3 legacy-lane migration) each get their own wave so a
  regression is unambiguously attributable and file contention is zero.
- **Run/meta boundary + git discipline:** parallel agents in `isolation: worktree`; verify branch
  topology before every merge; push `main` + mirror the board after every merge; one worklog per
  task naming the commit SHA + a **debt ledger** (net LOC removed + what duplication/coupling was
  retired) + a Design-deviations section.

## What exists today (as-built anchors — cite these, not the report's prose)

Each anchor is the concrete surface a task edits. Phase-2 designs cite exact APIs; these are the
load-bearing facts the breakdown is built on (verified in-repo 2026-07-09).

- **R2 / V1 — index-aligned weights:** `data/junk/junk_catalog.gd` holds `items: Array[JunkItem]`
  **and a parallel `spawn_weights: PackedFloat32Array` "index-aligned with items"**
  (`junk_catalog.gd:13-15`). `junk_catalog.tres` today: 8 items + `spawn_weights =
  PackedFloat32Array(40, 30, 18, 14, 4, 8, 5, 2)`. Inserting an item mid-array silently misaligns
  every weight below it. **Design tension already in the file:** the catalog's own docstring argues
  rarity is *"a property of a spawn context, not of the item's identity, so a future second catalog
  can reweight the shared item set without editing every .tres"* — i.e. the file itself argues
  AGAINST the report's "put the weight on JunkItem" option, and FOR a by-id map on the catalog. The
  weighted read is in `systems/depth/junk_placer.gd` (the only weighted consumer). CI has a catalog
  validation check. **(DR-2 resolves which representation.)**
- **R3 / V2 — dual-emit opposition signals:** `systems/event_bus.gd` (60 signals) carries the M1.9
  **generic** family `opposition_event(id, kind, …)` + `opposition_killed_player` **alongside six
  legacy per-type hazard signals** (R1–R4 era). `opposition_event` has 25 emit call sites (the
  heaviest emitter in the bus). Every def-driven hazard host emits both; `systems/telemetry/` must
  count from one family only to avoid double-counting. Retirement is already flagged post-gate
  (SG3, the M1.9 re-gate). V2 removes the six legacy signals + their emits + their telemetry/consumer
  reads, leaving only the generic family.
- **R4 / V3 — two hazard lanes:** `systems/spawning/encounter_builder.gd` has **two lanes**: the
  **deck lane** (bands 2–4: spends a credit budget over a profile's `opposition_deck`, filtered by
  `min_band`, param-merged def < deck < rc) and the **legacy lane** (band_greybox only: the
  hardcoded K5 "fair-share" machine for pingpong/bomb/spike driven by `rc.h*_*` knob groups in
  `data/run_config/run_config.gd`). Pursuer/pingpong/bomb/spike also spawn through hardcoded
  `main_game.gd` seams. The six newer hazards are data-only `OppositionDef` + `DeckEntry`. V3 folds
  the legacy four into the deck lane: band_greybox gets a real `opposition_deck`, the fair-share
  machine + the ~30 special-cased `rc.h*_*` knobs are deleted, and the "adding a legacy-style
  hazard touches many files" path disappears — leaving **exactly one way to add an opposition**.
  Requires OppositionDefs for pursuer/pingpong/bomb/spike (bomb/spike/pursuer may already have def
  forms — Phase 2 audits `data/oppositions/`).
- **R5 / V4 — GameState god-object:** `systems/game_state.gd` (752 lines) owns lifecycle
  (`start_run`/`extract_and_end_run`/`fail_run`/`end_run`), economy (`add_currency`/
  `sell_banked_junk`/`purchase`/pockets), the K2 quota ladder (with four snapshot fields that
  survive `end_run` ordering), and serialization (`to_meta_dict`/`from_meta_dict`). ~38 files
  reference it (heaviest: `main_game.gd` 27, `decision_hud.gd` 16, `shop_ui.gd` 14). Slot hardcoded
  to 0 at 5+ call sites. V4 splits along seams into **GameState-owned sub-objects** (Economy,
  QuotaLadder, slim lifecycle core) — **facade preserved**, so the 38 readers are untouched (DR-4).
  The quota snapshot-field workarounds should dissolve if quota evaluation stops depending on
  `end_run` clearing order.
- **R6 / V5 — duplicated interaction boilerplate:** `components/interaction/` is the detector/marker
  split (`Interactable` passive Area2D + `InteractionDetector` on the player). The **id-guard +
  parent-check + fat-finger lockout block is duplicated verbatim** across `JunkPickup`,
  `ExtractGate`, `DeparturePortal`, and `HubShop` (their own comments admit it). V5 extracts it into
  a tiny `InteractionOwner` helper (or a method on `Interactable` that owners connect through) and
  removes the four copies.
- **R7 / V6 — hand-rolled salted sub-streams:** `RNG` (`systems/rng.gd`) is the seeded autoload.
  Pockets/exits (`game_state.gd:16,22` — `POCKETS_RNG_SALT`, `EXITS_RNG_SALT`, seeded
  `run_seed ^ SALT`), flavor stages (`band_pipeline.gd:174` `_stage_seed` = `hash_combine`),
  and `junk_placer.gd:26` (`_JUNK_SALT`) each hand-roll a local `RandomNumberGenerator` sub-stream
  to avoid perturbing the layout stream. V6 promotes this into `RNG.substream(salt)` (and/or
  `RNG.substream(salt, index)` for the staged form) so the idiom is one discoverable call —
  **byte-identical to each current derivation** (the two idioms must both be reproduced or each
  call site proven equal; a fp move is a bug).
- **R8 / V7 — unbounded telemetry log + hardcoded analysis path:** `systems/telemetry/` writes
  `user://telemetry/run_log.jsonl` as **a single unbounded roller** (rotation explicitly deferred);
  `jsonl_writer.gd` is the dumb appender. The analysis script `analyze_m1_2.py` (under
  `tools/` / worklog analysis) **hardcodes each round's input path**. V7 adds per-session or
  size-capped rotation and gives the analysis script an `argv` input.
- **R9 / V8 — serial scene-test boot cost:** ~63 self-quitting scene tests each boot a fresh
  headless Godot process, serially, plus 15 per-milestone RG capstones — linear boot-cost growth
  with a known deadlock constraint (no concurrent headless instances against one project — see the
  `godot-headless-test-invocation` memory). Nothing is wrong today. V8 (cheap-now scope) records
  suite wall-clock in CI to expose the trend; sharding is deferred (DR-5).
- **R10 / V9 — housekeeping:** empty placeholder folders `data/items/`, `data/recipes/`,
  `data/upgrades/`, `data/enemies/` (all confirmed 0 files); the **declared-but-dead `run.sav`**
  path in `save_manager.gd:8` (documented, never implemented); and the 5+ hardcoded slot-0 call
  sites (noted for the future multi-slot UI, not changed now). V9 deletes the superseded folders
  (`data/items/` — old Item class folded into JunkItem; `data/enemies/` — superseded by
  `data/oppositions/`), keeps `recipes/` + `upgrades/` only if M2 will fill them (DR-6), and
  resolves run.sav (implement or delete — DR-6).
