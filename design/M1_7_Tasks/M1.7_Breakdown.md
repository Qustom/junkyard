## 1. The one thing M1.7 must prove

M1.0–M1.6 built a real surface-and-dive loop, but the player is still a **teal `ColorRect` with a triangle nose**. M1.7
replaces that greybox with the **first real character sprite** — the `player_basic_template` (red flannel over green hoodie,
empty hands), 8-directional, with **walk**, **pickup**, **throw**, and **idle** (the 8 static rotation poses). The one thing
to prove: **the player reads as an actual animated character — directional, with legible walk/idle and action animations for
pickup and throw — in both the Hub and the Dive, without regressing the loop or its determinism**, and with a **debug switch
back to greybox**. This is the iteration that stands up the **art-integration pipeline** (PixelLab frame sequences → Godot
`SpriteFrames` → an in-engine directional state machine driven by the *existing* movement/aim/EventBus seams) — the template
every future character, enemy, and outfit variant follows.

## 2. Scope guardrails (what M1.7 is and is NOT)

- **Visual only. Zero gameplay/economy/generator change.** The sprite is a *renderer* hung on the existing `Player`
  `CharacterBody2D`. The collision shape (`CircleShape2D` r=14), `collision_layer`/`mask`, movement tuning
  (`player_movement.tres`), aim/throw seams, and all RNG are **untouched**. The proc-gen determinism fingerprint must stay
  byte-identical: **all-off `RunConfig` default fp = `e943ac9c8bc1`**.
- **The debug "disable player art" toggle is NOT a `RunConfig` knob.** It is a **view-only debug switch** that lives OUTSIDE
  the `config_menu` MANIFEST / `has_full_coverage()` set. The **89-knob count must hold** and the coverage assertion must still
  pass — the toggle is a separate Meta-tab control wired to an EventBus signal, never a `RunConfig` `@export` field.
- **Art OFF == M1.6 behavior, byte-for-byte.** With the debug toggle set to *disable art*, the player renders the existing
  greybox (`Visual` `ColorRect` + `Nose`) AND the brief pickup/throw movement-lock is inactive — i.e. movement/feel is
  identical to M1.6. The greybox nodes are **retained** in `player.tscn` as the fallback, not deleted. Default = **art ON**.
- **Drive the animation off existing seams — add no new gameplay signals.** Direction = quantize the existing `facing`/`aim`
  (post-L6 it follows mouse / right-stick). Walk vs idle = the existing `velocity`. Pickup = `EventBus.junk_picked_up`. Throw =
  `EventBus.item_thrown`. The ONLY new EventBus signal is the **debug** one (`debug_player_art_toggled` or equivalent) — a
  tooling signal, not a gameplay one. `run_ended` arity stays locked; telemetry stays additive.
- **Pixel art, filter OFF** (project `default_texture_filter=0`, already nearest). Frames are 124×124 RGBA, LFS-tracked
  (`.gitattributes` already covers `*.png`). They are **copied into `Game/`** (e.g. `res://art/player/…`) because
  `art_workshop/` lives at the repo root, outside the Godot project — `res://` can only see assets under `Game/`.
- **The movement-lock is the only feel change, and it is gated.** Brief root during pickup/throw, ON only when art is ON.
  Tunable lock duration; default short. No other input/feel change.
- **NOT in M1.7:** dive-gear / alternate outfits, enemy/NPC sprites, run/death/hurt animations beyond the 4 supplied states,
  a shader/material pass, normal maps, footstep audio, or any band/art/generator change. Those are later iterations off this
  same pipeline.

## 4. Dependency map

```
N0 (import + SpriteFrames + signal)
   └─> N1 (player visual FSM)   ← needs player_frames.tres + the AnimatedSprite2D
          └─> N2 (debug toggle) ← swaps the visual N1 builds; emits the N0 signal
                 └─> RG1 (build + verify + publish)
                        └─> RG2 (telemetry/readability) ─> RG3 (verdict)
```

- **N0 blocks everything** — it produces the asset (`player_frames.tres`) N1 renders and the EventBus signal N2 emits.
- **N1 blocks N2** — N2's runtime swap targets the `AnimatedSprite2D`/greybox seam N1 establishes. N2's *menu-UI* half (the
  Meta-tab `CheckButton` + CSV string) is file-disjoint from N1 and MAY be drafted in parallel, but it **integrates after N1**
  (the player-side swap handler is the contract). Given the small size, the practical order is **strictly sequential**:
  N0 → N1 → N2, single build wave.
- **No parallel-collision management needed** — one writer per file per task (N0 owns `event_bus.gd` + the asset; N1 owns
  `player.tscn`/`player.gd`/`player_visual.gd`; N2 owns `config_menu.gd`/`.tscn`/CSV + adds a listener seam in the player that
  N1 has already set up). Worktrees optional (sequential).

## 6. Cross-cutting contracts (the M1.7 invariants every task holds)

1. **Determinism unmoved.** All-off `RunConfig` fp stays `e943ac9c8bc1`. The sprite touches no RNG and no `RunConfig` field.
2. **89-knob count holds.** The debug art toggle is a **view-only** switch outside the `config_menu` MANIFEST and
   `has_full_coverage()` set; `test_config_menu` / `test_run_config` counts stay 89.
3. **Art-OFF = M1.6 byte-for-byte.** Greybox retained as fallback; movement-lock inactive when art is OFF; default = art ON.
4. **Existing seams only for gameplay.** Direction/idle/walk/pickup/throw all derive from `facing`/`aim`/`velocity`/
   `junk_picked_up`/`item_thrown`. The single new signal is `debug_player_art_toggled` — tooling only.
5. **Collision + movement untouched.** `CircleShape2D` r=14, layers/masks, `player_movement.tres` unchanged; the sprite is
   scaled/offset to read against the existing body, not to redefine it.
6. **Pixel-art discipline.** Filter off (project default nearest); frames LFS; **COPIED — never moved —** from `art_workshop/`
   into `Game/` so `res://` can see them. **Exploration assets stay in `art_workshop/` untouched to preserve history**
   (standing rule, all iterations): an `explorations` source is duplicated into the game dirs, never relocated.
7. **Standing process:** worklog per task naming a real commit SHA; verify branch topology before every merge (qa git-switch
   leak — memory); push `main` + mirror the board after every merge; wave close-out deviation sweep; Director dispositions.

## 7. Open questions deferred to the per-task designs (Phase 2/3)

- **N0:** SpriteFrames vs. one `AnimatedSprite2D` with 32 named clips vs. an `AnimationPlayer`/`AnimationTree` blend — pick the
  simplest that supports 8-dir × 4-state with one-shot pickup/throw. FPS per clip (walk cadence vs. real speed; pickup/throw
  duration vs. the chosen lock window). Sprite scale + Y-offset so the 64px-on-124px-canvas character sits on the r=14 body.
  Whether the 8 idle `rotations` are 1-frame "animations" or just frames selected on the AnimatedSprite2D.
- **N1:** The 8-direction quantize boundaries (angle → S/SE/E/NE/N/NW/W/SW) and any hysteresis to stop diagonal flicker.
  Walk↔idle velocity threshold. Movement-lock mechanism (zero input vs. zero velocity vs. an input gate) and its default
  duration; what happens if the player throws mid-stride (snap to idle-pose-while-locked, or freeze the current frame).
  Z-ordering of the sprite vs. the `Nose`/world. Whether pickup even has a felt moment (interact is near-instant) — does the
  5-frame clip play fully under the lock, or is it cosmetic.
- **N2:** Exact Meta-tab placement + label; whether the toggle persists (a debug pref) or resets each launch (recommend
  **session-only**, no save write — it's a debug aid); whether it also shows/hides the `Nose`. Confirm the coverage assertion
  is keyed off MANIFEST (not "every child control") so a non-field `CheckButton` doesn't trip it.
