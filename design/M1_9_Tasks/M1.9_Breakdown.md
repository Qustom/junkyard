**The one thing this version must prove:** *adding content is data, not engineering.* The two explored
architectures land as working code — a policy-free `SpawnService` + `EncounterBuilder` for oppositions,
and a `BandProfile`-driven `BandPipeline` for bands — and are then **proven end-to-end by shipping 2 new
hazards and 1 new band that are (almost) entirely `.tres` data + small reusable parts**, reachable
in-game through a second hub portal. If the two new hazards ship as "def + component" and the new band
ships as "profile + stages," with the all-off baseline byte-identical throughout, M1.9 succeeds.

## Scope guardrails

- **Socket backend ONLY.** No `CaveBackend`, no `ScatterBackend`, no WFC/grammar (the exploration's own
  recommendation: build those only after a low-sightline/open-field band proves fun at a gate). The new
  band differentiates via **archetype params + flavor stages + palette/deck on the existing socket
  backend**.
- **Opposition migration phases A–D land in M1.9; Phase E is the proof** (the 2 new hazards). Legacy
  R1/K5 `RunConfig` `@export` groups **stay untouched** during migration (the exploration's contract) —
  no existing preset or telemetry breaks mid-migration.
- **The all-off `RunConfig` fingerprint `e943ac9c8bc1` stays byte-identical** through every wave — the
  permanent control. Likewise `tests/test_bandgen_determinism.gd` fingerprints must **byte-match through
  the orchestrated `BandPipeline` path** (band Phase-A acceptance): the `band_greybox` profile with empty
  principles/flavors reproduces today's band exactly.
- **Knob count may grow** (new generic levers `oppositions_enabled`/`param_overrides`, plus generated
  per-def sections), but the **coverage-assertion discipline is extended, never dropped**: the existing
  89 hand-authored rows keep their build-time assertion, and the new per-def net asserts
  `params.keys() == param_schema` keys for every loaded def. Fail-loud on drift, per def.
- **Determinism contract (non-negotiable, from both explorations):** no global `RNG` in generation-time
  placement; per-stage/per-client sub-seeds (`_derive_seed`/salt pattern); generation-time clients are
  RNG-free stable walks; mid-run clients (death-spawn, debug menu) are run-state and never touch the
  layout stream. The locked `setup(cfg, player, spawn_ctx)` handshake is **unchanged** — entities need no
  edit to be driven by the service.
- **EventBus pre-declare rule (K0 pattern):** ALL new/changed M1.9 signals are pre-declared on `main` in
  Wave 1 by S0 — `opposition_event`, `opposition_killed_player`, and the band-selection routing signal —
  payloads primitives-only. Legacy per-type signals dual-emit during migration; retirement is post-gate.
- **No save-schema change.** Band choice is run-state (the portal picks the profile for *this* dive);
  the new band's portal is **always present on the hub for now** (Director's directive) — unlock
  persistence is deferred to a future version.
- **Placeholder art only; PixelLab paid runs are Director-gated.** New-hazard sprites and the new band's
  palette start as greybox/retone-level placeholders; any PixelLab generation needs an explicit Director
  OK (STATUS Blocked table).
- **Run/meta boundary + single-writer-per-`.gd`-file per wave** hold. `main_game.gd` has a designated
  sole writer each wave (S0 in Wave 1, S3 in Wave 3, nobody else ever).
- **No M2 dependencies:** no player HP pool → no Gas/Electrified-style Field hazards this version. The
  2 new hazards must fit the M1 lethality model (`*_kills`-gated `fail_run`, emit-always).
