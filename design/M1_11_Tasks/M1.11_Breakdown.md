**The one thing this version must prove:** *the seams hold at N = 3, with declining marginal
cost.* M1.9 proved "new content on existing machinery is data"; M1.10 proved a genuinely
different generator slots in behind `BandPipeline` (and, en route, made materialisation
**backend-agnostic** — `_build_synthetic_piece` hosts any `floor_cells`-carrying synthetic
piece, and the unedited `SocketSealer` is the single wall-writer for every backend). M1.11
proves the pattern is now *routine*: backend #3 (`ScatterBackend` — no pieces, no CA, a
poisson-scattered open arena) should cost **less** than backend #2 did (target: ~0 new
downstream lines — the materialisation path should already host it), and the opposition model
extends to a **threat axis nothing shipped exercises — at-range / projectile threat** (all 9
shipped defs are contact-lethal) — as def + one new component each, zero engine rework. The
measure of success is the **cost ledger**: each task's worklog records the bespoke code needed
beyond the promised backend/component — the N=3 trend line IS the scalability answer UG3 judges.

## Scope guardrails

- **ScatterBackend ONLY — no WFC, no grammar, no archipelago.** One new backend is the
  experiment; the exploration's own matrix strikes archipelago ("gaps fight the connectivity
  invariant") and defers WFC/cyclic-grammar indefinitely. Maze/labyrinth/grid archetypes are
  socket- or CA-expressible — not a *different* generator, so not this version.
- **The FOUR existing controls stay byte-identical at every wave boundary:** the all-off
  `RunConfig` fingerprint **`e943ac9c8bc1`**, the `band_greybox` fingerprint, the `band_two`
  fingerprint, and — new this version — the **`band_three` fingerprint** (M1.10's shipped cave
  band is now itself a control, absolute golden fp pins per the T3 precedent). Scatter code
  must be reachable only through a `backend == "scatter"` profile.
- **Determinism contract (non-negotiable):** the scatter backend reseeds via the existing
  `RNG.seed_from(seed)` discipline; **all sampling is order-stable** (sorted candidate order,
  fixed accept/reject sequence — the exploration's called-out scatter gotcha, the sibling of
  M1.10's sorted-flood-regions rule); connectivity is guaranteed **by construction**
  (cover stamping must never disconnect the floor — min-spacing + clear-lane rules) or by
  **deterministic CARVE**, never retry-loops on the global stream. Same `(profile + seed +
  rc)` key → same `fingerprint()`, byte-for-byte, forever.
- **No new opposition machinery.** Lobber + Sentry ride the S0/S2/S3 stack exactly as shipped:
  `OppositionDef.tres` + `param_schema`, one new `OppositionComponent` each, spawned by
  `EncounterBuilder`/`SpawnService`, surfaced by the generated menu sections + per-def
  bijection net. A projectile/marker sub-node lives inside the component's own scene ownership
  — it is not shared machinery. Any needed edit to a *shared* host/component file is a flagged
  deviation with a designated single writer, not silent sprawl.
- **M1 lethality model holds:** both new oppositions are Actors with `*_kills`-gated
  `fail_run` (params-carried, per the M1.9 Wave-4 canon). Lobber blast and Sentry bolt are
  both kills-gated. No player HP pool, no damage-over-time.
- **Knob model frozen; per-def net extends itself.** No new hand-authored `RunConfig` levers.
  New defs appear via the count-agnostic generated Oppositions tab; the per-def params↔schema
  bijection extends to **11 defs** (9 shipped + 2 new). Coverage assertions never dropped.
- **No save-schema change.** The fourth portal is always present (standing Director directive);
  band choice stays run-state through `dive_requested(band_id)` → `GameState` staging →
  `BAND_ROUTES`.
- **Placeholder art tint-only** (`palette_tint` tier-1, D-RAT-4/5 precedent). The arena and its
  cover materialise as greybox geometry; PixelLab runs are Director-gated; pixel filter OFF;
  copy-not-move from `art_workshop/`.
- **Run/meta boundary + single-writer-per-`.gd`-file per wave** hold. `main_game.gd` has ONE
  designated writer through Wave 2 (U1 — expected to write **nothing or nearly nothing**; that
  near-zero diff is the version's headline evidence); U4 writes exactly the one `BAND_ROUTES`
  row + the hub portal instance in Wave 4 (per-wave single-writer, the M1.10 amendment-11
  wording). `band_pipeline.gd`/`band_profile.gd` are U0's.
- **No M2 dependencies.** Open-field landmark navigation / "too exposed" feel ships as-is and
  is a UG2/UG3 watch-item, not a build task.
