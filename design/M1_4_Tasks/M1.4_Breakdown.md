## 1. The one thing M1.4 must prove

M1.3 made the fun config the default and filled the big rooms, but the playtest exposed the loop as **low-stakes and
low-variety**: the money has no *reason* (nothing is at risk if you under-perform), there is only one kind of danger
(the pursuing hazard), the extract is a fixed known spot, the timer/visibility aren't controlled variables, and a
movement jitter nags every run. **M1.4 gives the run real stakes (a per-run quota whose failure wipes you), triples
the danger vocabulary (ping-pong, bomb, rotating spikes), makes the camera's visible area and the timer controlled
+ configurable, randomizes/multiplies the exit, and fixes the jitter — then re-gates for a possible "go."**

## 2. Scope guardrails (what M1.4 is and is NOT)

- **Greybox + configurable-not-balanced**, exactly as M1.1/M1.2/M1.3. Every new lever is a swept `RunConfig` knob; the
  *value* is the Director's to sweep, not ours to finalize. New hazards are greybox shapes (colored `Polygon2D` tells),
  not the M2 enemy-AI slice.
- **The all-off `RunConfig` default stays the permanent baseline control** (determinism fp=`e943ac9c8bc1`, telemetry
  comparability with M1.0→M1.3). Every new knob defaults **off/neutral** so an unconfigured run still reproduces M1.0
  byte-for-byte. The fun values ship in `make_default_play_preset()`, never by changing the code-level all-off defaults.
  This is the load-bearing carried contract.
- **NOT** new bands, new real art, a generator rewrite, a meta/economy layer beyond the quota, or combat. The quota is a
  single gate + a wipe, not a debt/life-sim economy (that's M2+). New hazards reuse the existing per-depth + per-room
  spawn seam; they don't add pathfinding/navmesh/behaviour-trees.
- `run_ended` arity stays locked (quota-fail reuses it like timeout/death); telemetry stays additive (`data` fields only).
  **The ONE exception:** K2's quota meta-state requires a **save-schema bump (META v2 → v3) + an ordered migration step +
  a QA fixture** — the standing rule on any schema change (`CLAUDE.md` → Saves).
- Config-marked telemetry continues; the re-gate compares M1.4 cohorts to the M1.0/M1.1/M1.2/M1.3 baselines on the same metrics.

## 6. Cross-cutting contracts (carried from M1.1/M1.2/M1.3)

- **Configurable knob + config-marked telemetry**, all-off default reproduces the prior baseline as the permanent control.
  Every new knob joins `RunConfig.to_flat_dict()` + the CFG coverage assertion; update `tests/test_run_config.gd` /
  `tests/test_config_menu.gd` knob counts. Spatial knobs that feed `fingerprint(seed+config)` keep the **neutral default
  byte-identical** (fp=`e943ac9c8bc1`) — non-neutral configs are allowed to move fp (like R4 branching / J4 corridor weight).
- **The default play-preset is a separate artifact** (`make_default_play_preset()`), NOT the code-level all-off default.
- **Determinism for K7 (exits):** exit placement must be **run-config-keyed** (default = today's single fixed `GATE_SPAWN_OFFSET`)
  so the all-off control's fingerprint never moves. If random placement consumes the RNG, route it through a **local sub-stream**
  (the B3/E3 pattern — `run_seed ^ salt`), never the global RNG mid-generation, OR keep it pure run-state (post-generation placement).
  New-hazard spawn placement (K5) is pure **run-state** (never feeds `fingerprint()`), like the R1 hazards.
- **Save schema (K2 only):** bump META `v2 → v3`, add ONE ordered migration step, add a QA fixture — the standing rule.
  Quota/run-number that persists + wipes is **meta-state**; design the run/meta boundary explicitly in Phase 2.
- **`run_ended` arity locked:** quota-fail ends the run through the existing path with a new `reason` (e.g. `&"quota_fail"`),
  then the wipe runs as a *separate* meta operation after the run resolves — no arity change, no parallel run-end.
- **Single-writer-per-`.gd`-file** within a wave; **pre-declare every new EventBus signal on `main`** (K0 does this for the
  whole milestone up front, so no per-wave signal pre-declare is needed). **Parallel agents in `isolation: worktree`**; verify
  each branch's topology before merge (the qa-agent `git switch` leak — orchestrator memory); push `main` after every merge;
  mirror task status to the board; run the wave close-out deviation sweep (Director dispositions) after every wave.

## 7. Open risks to resolve in Phase 2/3

- **Quota run/meta boundary & timing (K2):** *When* is the quota checked — at extract/sell only, or on every run end
  (so a death/timeout with an unmet quota = game over)? Is the quota met by **this run's banked/sold value** or by
  **cumulative money ≥ threshold**? Does the run-number live in meta (persisted, escalates, resets-to-1 on wipe)? What
  exactly does "full wipe" clear (money + banked_junk + recipes + run-number → all to defaults)? These are load-bearing —
  Phase 2 designs them, Phase 3 / Director ratifies. The wipe verdict itself is **already Director-FINAL: full roguelite wipe.**
- **Camera approach (K3) + jitter (K6):** content-scale stretch (`canvas_items` + fixed base resolution) vs dynamic camera
  zoom-to-fit, and how the chosen approach interacts with pixel-art (filter OFF) and the jitter root cause (physics
  interpolation? camera smoothing on a physics-body child?). One seam; resolve the root cause before choosing the fix.
- **New-hazard config shape (K5):** do the 3 hazards get their own `RunConfig` groups (e.g. `h_pingpong_*`, `h_bomb_*`,
  `h_spike_*`) each with an `enabled` + count + depth-scale, parallel to R1? How does "stays in its room" get the room's
  bounds (reuse `floor_cells` per piece)? Phase 2 defines the knob set K0 then pre-declares.
- **Exit determinism + multiplicity (K7):** how many exits, how often, how depth scales the count, and the "always one at
  spawn" toggle — without moving the all-off fingerprint. Defaults must equal today's single fixed gate.
- **Timer surfacing (K4):** is the length a `RunConfig` knob, a `DiveClockConfig` field exposed through the preset, or both?
  Where does the warning cue live (HUD `decision_hud` vs a new node) and is it visual-only or audio too?
