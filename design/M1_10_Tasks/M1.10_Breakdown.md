**The one thing this version must prove:** *the M1.9 architectures scale along their second
axis.* M1.9 proved "new content on the existing machinery is data" (new defs, new profile —
same socket backend). M1.10 proves the harder half of each claim: **a band built by a genuinely
different generator** (`CaveBackend`, cellular automata — no pieces, no sockets) slots in behind
the same `BandPipeline` interface with the entire downstream stack (grade, junk, encounter
population, materialisation contract, telemetry, debug menu) **reused unchanged**, and **two
more oppositions** land as def + one new component each, with zero engine rework. The measure of
success is the *cost ledger*: each task's worklog records how much bespoke code was actually
needed beyond the promised backend/component — that ledger IS the scalability answer TG3 judges.

## Scope guardrails

- **CaveBackend ONLY — no ScatterBackend, no WFC, no grammar.** One new backend is the
  experiment; two would blur the cost measurement. Open-field/scatter stays a future candidate
  (the exploration's own sequencing).
- **The three existing controls stay byte-identical at every wave boundary:** the all-off
  `RunConfig` fingerprint **`e943ac9c8bc1`**, the `band_greybox` profile fingerprint, and —
  new this version — the **`band_two` profile fingerprint** (M1.9's shipped content is now
  itself a control). Cave code must be reachable only through a `backend == "cave"` profile.
- **Determinism contract (non-negotiable):** the CA backend reseeds via the existing
  `RNG.seed_from(seed)` discipline; **all cave iteration is order-stable** (sorted flood
  regions, fixed cell-scan order — the exploration's called-out gotcha); connectivity repair is
  **deterministic CARVE** (the `ConnectivityGuarantee` stage's existing CARVE mode), never
  retry-loops on the global stream. Same `(profile + seed + rc)` key → same `fingerprint()`,
  byte-for-byte, forever.
- **No new opposition machinery.** Ambusher + Burrower ride the S0/S2/S3 stack exactly as
  shipped: `OppositionDef.tres` + `param_schema`, one new `OppositionComponent` each, spawned
  by `EncounterBuilder`/`SpawnService`, surfaced by S4's generated menu sections + per-def
  bijection net. Any needed edit to a *shared* host/component file is a flagged deviation with
  a designated single writer (see wave rules), not silent sprawl.
- **M1 lethality model holds:** both new oppositions are Actors with `*_kills`-gated
  `fail_run` (params-carried, per the Wave-4 M1.9 canon). No player HP pool, no Field/zone
  hazards, no damage-over-time.
- **91-knob model frozen; per-def net extends itself.** No new hand-authored `RunConfig`
  levers. New defs appear via the count-agnostic generated Oppositions tab; the per-def
  params↔schema bijection extends to 9 defs (7 shipped + 2 new). Coverage assertions never
  dropped.
- **No save-schema change.** The third portal is always present (M1.9 precedent, Director's
  standing directive); band choice stays run-state through the existing
  `dive_requested(band_id)` → `GameState` staging seam → `BAND_ROUTES`.
- **Placeholder art tint-only** (`palette_tint` tier-1, D-RAT-4 precedent). Cave floor/walls
  materialise as greybox geometry; PixelLab runs are Director-gated; pixel filter OFF;
  copy-not-move from `art_workshop/`.
- **Run/meta boundary + single-writer-per-`.gd`-file per wave** hold. `main_game.gd` has ONE
  designated writer this version (T1, Wave 2 — nobody else ever). `band_pipeline.gd` is T0's.
- **No M2 dependencies.** Depth signposting in caves ("deeper = farther home" is less
  eyeballable than a spine) ships as-is and is a TG2/TG3 watch-item, not a build task.

## What exists today (as-built anchors — cite these, not exploration sketches)

- **Backend seam, already declared:** `BandProfile.backend` enum carries `"cave"` as a declared
  value (`data/bands/band_profile.gd:26`) and `BandPipeline.generate` fail-louds on it at the
  Phase-A wiring guard (`systems/bandgen/band_pipeline.gd:45-48`) — the cave backend replaces
  that guard with dispatch. `BandProfile.validate()` has a socket-only branch
  (`band_profile.gd:82-95`) needing a cave branch.
- **Pipeline stage stack (T0 slots in as STAGE 1-2):** `BandPipeline.generate(profile, seed, rc)`
  → backend/archetype (today: `BandGenerator.new().generate` verbatim, `band_pipeline.gd:80`) →
  S5 flavor loop + `ConnectivityGuarantee` (CARVE/ASSERT modes, `:93-107`) → `DepthGrader.grade`
  + `compute_return_distance` (`:112-113`). Per-stage sub-seeds via `_stage_seed` (`:143`).
- **Downstream consumes FLOOR-cell 4-adjacency only:** `DepthGrader` (BFS depth), `JunkPlacer`
  (loot on `floor_cells`, `_JUNK_SALT` sub-stream), `EncounterBuilder.populate` (walks pieces in
  stable order, credit budget × `instability(band_depth)` = 1.0 + 0.15·(depth−1) → band 3 =
  **1.30**). None touch sockets — the exploration's reuse claim, now load-bearing.
- **Materialisation is piece-instance-based (T1's problem):** `_materialise_band`
  (`scenes/game/main_game.gd:818-836`) walks `band.pieces`, parents each authored
  `p.instance` (a ZonePiece scene), then `SocketSealer.seal_unused_sockets` caps unmated
  sockets. A cave band has **no authored instances and no sockets** — it needs a synthetic
  materialisation path (runtime-built greybox geometry + collision from `floor_cells`) and a
  void-sealing rule that doesn't assume sockets.
- **Band fingerprint:** `Band.fingerprint()` = ordered `piece_id@offset#mated` sha256. Synthetic
  cave pieces must feed it stably (T0 defines the synthetic piece identity).
- **Opposition stack (T2a/T2b ride it):** `SpawnService` (per-dive node, caps live-registry-
  derived, `ignore_entry_safety`/`ignore_room_cap` ctx escapes) + `EncounterBuilder` (deck lane
  def-major, J2 even-spread — FBM19 as-built) + `OppositionDef`/`DeckEntry` (def params <
  deck-entry < `rc.param_overrides`). Component set as-built
  (`scenes/hazards/components/`): `OppositionComponent` base, `ChaseMove`, `ChargeLane`,
  `PatrolMove`, `SpinMove`, `StraightBounceMove`, `ProximityTrigger`, `DepthLingerTrigger`,
  `TelegraphFSM`, `LethalContact` (has the externally-driven contact seam), `ThrowInteraction`
  (+ `thrown_item.gd`'s locked `resolve_throw_death` seam). Defs at `data/oppositions/` (7).
- **Routing:** `BAND_ROUTES` (`main_game.gd:49`) maps route key → profile id (`&"near"` →
  `band_greybox`, `&"band_two"` → `band_two`); `_resolve_band_profile` consume-on-read off
  `GameState.consume_pending_dive_band()`; hub portals emit `dive_requested(band_id)`
  (`departure_portal.gd`, per-instance `interactable_id` + route key override). Telemetry
  `band_id` = the ROUTE key, stamped on `run_started`.
- **Debug surface:** S4's generated Oppositions tab is count-agnostic (proven 4→6→7 defs);
  FBM19b's IN-DECK chips read deck membership per band. New defs need zero menu code.

## Open questions (breakdown-level — Phase 2 designs expand, Phase 3 resolves, Director ratifies)

1. **Which 2 oppositions?** Recommend **Ambusher + Burrower** — they are the pair the caverns
   exploration names as the archetype's reason to exist (both *need* bad sightlines to read as
   fair), and each proves a component-model axis nothing shipped exercises (concealment;
   phased vulnerability with collision cycling). Alternates: Lobber (cave-compatible; mostly
   reuses the bomb blast model — a weaker architecture proof), Sentry (needs straight lanes —
   wrong band). *Vision/fun — Director ratifies.*
2. **Band 3 identity** — name/fiction/palette direction (2–3 pitches from T3's design;
   deeper/alien per the GDD escalation, `band_depth=3`). *Tone — Director.*
3. **Cave materialisation approach** — runtime-built greybox geometry (ColorRect/Polygon2D
   walls per synthetic piece) vs a generated `TileMapLayer`. Phase 2 (T1) researches both and
   recommends; the b3 "tile-world vs piece-world" flag. *Technical — resolve on merit.*
4. **Void-sealing for socketless bands** — backend-emitted perimeter walls vs a geometry-keyed
   sealer sibling vs `SocketSealer` generalization. *Technical (T0/T1 seam) — resolve on merit,
   byte-safety for socket bands is the bar.*
5. **Synthetic-piece fingerprint identity** — how `floor_cells` feed `Band.fingerprint()`
   stably (hash of sorted cells vs region-anchored synthetic ids). *Technical — resolve.*
6. **Ambusher pounce lethality** — exploration recommends a nonfatal stagger, but M1 has no HP
   pool; recommend **`kills`-gated fatal pounce with a generous authored tell** (Wrecker
   fairness precedent), stagger deferred to an HP-bearing milestone. *Fun/fairness — Director.*
7. **Ambusher re-arm** — one-shot (spent after pounce) vs re-hide cycle. Exploration recommends
   one-shot for the first build; a re-hide period param can ship dormant. *Ratify.*
8. **Burrower tracking fairness** — exact-position decal (fair/trivial) vs vague zone
   (tense/feel-bad). Exploration recommends clear telegraph + authored `track_speed` slow
   enough to outwalk. *Fun/fairness — Director.*
9. **Deck exclusivity** — both new oppositions band-3-exclusive in M1.10 (clean A/B at TG2,
   mirroring D-RAT-2)? Recommend yes. *Director.*
10. **Cave flavors** — confirm flavors ship EMPTY on `band_three` (SetPieceInject/WearDecay are
    socket-built; the cave is its own flavor). *Scope — confirm.*
