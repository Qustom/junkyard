# M1.8 — Hub Art Dressing (Layout A · Vertical Spine) — Breakdown

> **Iteration version of M1.x.** Authored from the M1.7 breakdown as a template, per CLAUDE.md
> "Version breakdown authoring — the four-phase process." M1.8 is **Director-directed content
> opened ahead of the M1.7 re-gate verdict** (exactly as M1.7 was opened ahead of M1.6's verdict);
> M1.7's RG2/RG3 stay non-blocking.

**The one thing this version must prove:** the surface Hub can shed its greybox skin and read as a
*place* — a lived-in golden-hour salvage yard — using the placeholder Layout-A art **without
touching the loop's behaviour**. Money/quota/portal/shop all still work byte-for-byte; only the
*look* changes. If the dressed hub reads as "a junkyard you'd want to walk around in" and the loop is
unchanged, M1.8 succeeds.

## Scope guardrails

- **Art-only iteration.** No new gameplay systems, no `RunConfig` knob, no save-schema change, no
  economy/quota change. The all-off `RunConfig` fingerprint **must stay `e943ac9c8bc1`** and the
  config-menu knob count **must stay 89/89** — M1.8 adds no lever.
- **Placeholder art, not shippable.** The Layout-A assets are PixelLab placeholders
  (`art_workshop/map_layouts/layout_a_assets/`). M1.8 *integrates* them; a human pixel artist still
  owns the final art. This is the same bar as the M1.7 `player_basic_template`.
- **Preserve every functional contract** (the load-bearing reason this is low-risk):
  - `DeparturePortal` — `Area2D` with child `Interactable` (`interactable_id=&"portal"`,
    `prompt_text="Dive"`), collision_layer 4. **Visual only** changes (greybox `Body`/`BodyInner`
    `ColorRect`s → the `dive_gate` sprite + `portal_glow` behind it). The interact contract is untouched.
  - `HubShop` — `Area2D` + child `Interactable` (`interactable_id=&"shop"`, `prompt_text="Shop"`) +
    `ShopUI`. **Visual only** changes (greybox `Body` → `shack_door` sprite). Contract untouched.
  - `Player` spawn at `PlayerSpawn` (`hub.gd` reads `$PlayerSpawn`), `HubCamera`, `HudLayer`
    (`QuotaNotice`, `HubLabel`, `ControlsLabel`) — **node paths `hub.gd` reads must not break**
    (`$Player`, `$PlayerSpawn`, `$HudLayer/QuotaNotice`).
  - The room must stay **bounded** — the player cannot walk off the dressed yard. Keep the
    `Room/Walls` `StaticBody2D` collision (re-skin the wall *visuals* as scrap-wall, keep the shapes).
- **Determinism / pixel rules.** Texture filtering stays OFF (`default_texture_filter=0`, already set);
  all imported hub art inherits it. Any procedural tile placement is RNG-free (fixed layout, not
  `RNG`-seeded) — the hub is a static authored room, not generated.
- **Copy, never move.** Assets used from `art_workshop/` are **copied** into the Game library, leaving
  `art_workshop/` exploration history intact (memory: `art-copy-not-move-from-explorations`).

## What we're dressing — the source

- **Layout spec:** `art_workshop/map_layouts/staging_area_layout_a_dressed.md` (the vertical-spine
  blockout: street/spawn south → shack mid → dive gate north; ground bands; functional + dressing props).
- **Assets:** `art_workshop/map_layouts/layout_a_assets/` — **16 ground tiles** (32×32; 5 materials:
  asphalt `=`, dirt `.`, dirt-litter `░`, scrap-wall `~`, plank-floor `▓`) + **24 object PNGs** (native
  game px). Asset↔glyph map: `layout_a_assets/README.md`.
- **Target scene:** `Game/scenes/hub/hub.gd` + `hub.tscn` (currently greybox `ColorRect` floor + 4 wall
  `ColorRect`s; functional nodes are greybox `Area2D`s).

- **Definition of done:** `--import` clean; `hub_ground.tres` loads (16 usable tiles); a throwaway
  load check passes; assets present under `Game/art/hub/` AND still present in `art_workshop/`
  (copy, not move). No `hub.tscn` change in H0. Worklog + commit SHA.

#### H1 — Dress the Hub scene (Layout-A vertical spine)
- **Milestone:** M1.8 (Wave 1)   **Assignee:** general-purpose (+ environment-artist)   **BlockedBy:** H0
- **Goal:** Replace the greybox skin of `hub.tscn` with the dressed Layout-A spine, preserving every
  functional contract above.
  - **Ground:** replace the `Floor` `ColorRect` with a `TileMapLayer` (using `hub_ground.tres`) painted
    as the **3-band south→north spine**: asphalt `=` at the south street edge → packed-dirt `.` across
    the open yard (keep the **central spawn→shack→gate lane cleanest**) → dirt-litter `░` thickening
    toward the north, framed by a scrap-wall `~` border. Paint it **deterministically** (a small
    RNG-free `@tool`/`_ready` paint, or authored `tile_map_data` — agent's call; programmatic
    `set_cell` is recommended for legibility & correctness). Use the tile *variants* so the floor
    doesn't visibly repeat.
  - **Walls:** re-skin the four `Room/Walls` visuals as the scrap-wall border (sprite or scrap-wall
    tiles) but **keep the `StaticBody2D` collision shapes** so the room stays bounded.
  - **Functional props (visual swap only — contracts intact):**
    - `DeparturePortal` (north-center, the `╬╬` gate): swap `Body`/`BodyInner` `ColorRect`s for the
      `dive_gate` sprite; add the `portal_glow` sprite *behind/above* it (the cold-violet `P` lure).
      Interactable child + collision + `interactable_id=&"portal"` unchanged.
    - `HubShop` (the `D` shack): swap `Body` for the `shack_door` sprite; add the `workbench` + the
      `sort_table` props beside it as the `T` benches (decorative). Interactable + `ShopUI` unchanged.
  - **Dressing scatter:** place ~10–12 of the `o`-pool props (tire_stack, oil_drums, car_on_blocks,
    truck_cab, freezer, bathtub, cable_spool, pallet_cans, propane_tank, signpost, wheelbarrow,
    potted_plant, folding_chair, chalkboard, dog_bowl) per the spec's **placement rules**: keep the
    central lane clear, cluster at yard corners + the shack apron, bigger silhouettes (car/truck/freezer)
    near the scrap-wall border, litter thickening north. Pure visual — no new collision (props are
    decorative; the wall border owns bounding).
  - **z-ordering:** ground below, props above ground, the player above props it stands in front of
    (use `y_sort` on the props' parent so the player walks behind/in-front correctly — the room is
    top-down). Keep the HUD `CanvasLayer` on top.
- **Definition of done:** `--import` clean; **smoke green**; **all-off fp `e943ac9c8bc1`** unmoved;
  **89/89** knob count held (M1.8 adds no knob); the hub scene loads headlessly (a load/contract check:
  `$Player`, `$PlayerSpawn`, `DeparturePortal` Interactable id `portal`, `HubShop` Interactable id
  `shop`, `$HudLayer/QuotaNotice` all resolve); the room is still wall-bounded. **On-screen confirmation
  (Director, manual — headless can't render):** the spine reads south→north, the central lane is clear,
  functional props read as gate/shack, dressing sells the lived-in yard. Worklog + commit SHA + a
  **Design deviations** section.
