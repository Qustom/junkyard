### What the test asserts (real SaveManager path: `_load_var` → `_migrate_meta` → `from_meta_dict`)
1. Fixture really is v1 (raw read: `schema_version == 1`, no `banked_junk` key).
2. After `load_meta`, `schema_version == 2` (`META_SCHEMA_VERSION`).
3. Migrated dict gains `banked_junk = []`; `GameState.banked_junk` rehydrates to an
   empty typed `Array[JunkItem]` without crashing.
4. Every v1 field survives intact (money 1337, salvage 42, lore 9, exposure 73,
   knowledge_level 3, unlocked_recipes [recipe_alpha, recipe_beta]).
5. Round-trip: `save_meta` re-serializes at v2, leaves a `.bak` of the prior good
   file, and reload returns v2 with money intact (atomic-write + `.bak` exercised).

## Fixture approach chosen + template for future schema bumps
Chose **approach (a)** — a committed binary `.sav` fixture — over an in-memory build,
because pinning the actual on-disk v1 bytes is the stronger regression guard against
a `store_var`/migration drift. The test loads that exact committed file through the
production `load_meta` path (staged into a throwaway slot 9001).

**Template every future schema bump (N → N+1) follows:**
1. Add a stepwise `match` case to `SaveManager._migrate_meta` (default the new field).
2. Commit a binary `tests/fixtures/meta_v<N>.sav` (use `gen_meta_v1_fixture.gd`'s
   pattern: build the v<N> dict, `store_var(.., false)`).
3. Add a case to `test_save_migration.gd` that loads it, asserts the new field's
   default + survival of older fields, and round-trips once via `save_meta`/`load_meta`.
4. CI already runs the scene as a release gate — no workflow change needed per bump.
