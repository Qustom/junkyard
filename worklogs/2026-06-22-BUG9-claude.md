# Worklog — BUG9: invisible rotating-spike blades

- **Task:** BUG9 (M1.4 playtest bug). The rotating spike (K5c) was killing the player with no
  visible blade — "I don't see the blade at all." Surfaced after FB6/FB7 telemetry attributed the
  "no reason" deaths to `new_hazard_killed kind=spike depth=10`.
- **Milestone:** M1.4 (post-Wave-5 follow-up).
- **Assignee:** Claude (orchestrator, direct fix — small + well-isolated).

## Root cause (confirmed empirically)
`SpikeHazard._rebuild_tell()` built the 3-arm star as a SINGLE Polygon2D outline tracing
base+/tip/base- for each arm in sequence — an outline that weaves through the hub and
**self-intersects**. `Geometry2D.triangulate_polygon()` (ear-clipping, which Polygon2D uses)
returns **0 triangles** for a self-intersecting polygon, so the Tell rendered NOTHING. The kill
still fired because it's an analytic distance-to-segment test on `_angle`, not the polygon — i.e.
an invisible instakill. Verified with a headless `triangulate_polygon` check: current polygon → 0
triangles; per-arm quads → 2 triangles each.

## Fix
- `scenes/hazards/spike_hazard.gd` — `_rebuild_tell()` now emits ARM_COUNT separate convex quads
  (constant-width solid bars), each registered as its own island in `Polygon2D.polygons` so each is
  triangulated independently and can never self-intersect. Lethal geometry untouched.
- `tests/test_spike_hazard.gd` — new assertion (f): after setup, `Tell.polygons` has ARM_COUNT
  islands and each triangulates to >0 triangles (guards the invisible-blade class of bug).
