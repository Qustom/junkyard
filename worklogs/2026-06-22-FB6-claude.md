# Worklog — FB6: telemetry for the K-key debug_kill

- **Task:** FB6 (M1.4 playtest follow-up). Add telemetry for the debug-kill (K key) death so it is
  not a reasonless `cause=death` in the log. Arose from the Director's "a bit into the game the player
  dies, no reason" report — diagnosed (G4_findings_M1.4 / chat) as the `debug_kill` action.
- **Milestone:** M1.4 (post-Wave-5 follow-up).
- **Assignee:** Claude (orchestrator, direct micro-change — not dispatched; too small for a subagent).

## Root cause
`debug_kill` (key K, `project.godot` physical_keycode 75) → `GameState._unhandled_input` emits
`EventBus.player_died(&"death")` → `GameState._on_player_died` → `fail_run("death")`. The Telemetry
autoload subscribed to neither `player_died` nor `new_hazard_killed`, so a K-press produced a bare
`run_ended cause=death` with **no preceding row** — indistinguishable from a phantom/unexplained death.

## What changed
- `systems/telemetry/telemetry_schema.gd` — new additive event type `DEBUG_KILL = "debug_kill"`
  (+ added to `ALL_TYPES`). **SCHEMA_VERSION stays 1** (additive type string, no envelope/arity change).
- `systems/telemetry/telemetry.gd` — connect `EventBus.player_died` → new `_on_player_died(cause)`,
  which `_emit_row(DEBUG_KILL, {cause, depth, run_t_ms})` and flushes. Mirrors `_on_hazard_caught`
  (the row precedes the death `run_ended`, stamps run-elapsed itself, flushes for crash safety).
- `tests/test_telemetry_jsonl.gd` — `_drive_run` now emits `player_died(&"death")` before `run_ended`
  on a death run (mirrors the real flow); added an assertion that a `debug_kill` row exists carrying
  `cause`/`depth`/`run_t_ms` with `cause=="death"`.
