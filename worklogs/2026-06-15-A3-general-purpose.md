## What changed
Added the in-dive "light" clock — a single depleting run-state resource that drains
over a dive to create push-your-luck time pressure, plus a greybox meter and a demo
scene. `DiveClock` is the single source of truth; it resets/starts on
`EventBus.run_started`, stops on `run_ended`, drains in `_process`, emits
`dive_clock_changed` each frame, and emits `dive_clock_timeout` exactly once at zero.
Timeout *handling* stays out of scope (task E3 listens). Tuning is data-driven
(`DiveClockConfig`, 60s linear budget). The meter is a passive EventBus listener.

## Design deviations
1. **Keys off `run_started`/`run_ended`, not new `dive_started`/`dive_ended`.** Orchestrator-directed (wave-2 lock); `systems/event_bus.gd` and `systems/game_state.gd` left untouched. Handlers accept the real signatures (`band_id, seed` / `reason, duration_s, depth_reached`), unused. No Director sign-off needed — on-spec intent (the spec anticipated "dive_started may already exist").
2. **Greybox meter built inline** by the programmer rather than dispatching `ui-ux-designer` — flat `ProgressBar`, no real asset work. On-spec; no sign-off needed.
3. **Tuning + design recommendations from the spec's "Open questions" adopted**: `max_light=60`, `start_light=0`, `drain_per_second=1.0`; junk does NOT modify the clock; light as fuel via one guarded `modify_light` (wired but unused by M1 gameplay); `PROCESS_MODE_PAUSABLE`; transient per-dive node. `60` is flagged to the human as the single most playtested M1 number (a dial, not a commitment).

All three appended to `design/DESIGN_DEVIATIONS.md`.

## Handoffs / follow-ups
- **E3** (timeout handling) binds the exact signal name `dive_clock_timeout()` — confirmed canonical, already present in EventBus.
- **Dive-scene integration:** `DiveClock` lives in the run/dive scene; whoever builds that scene instances `systems/dive_clock.tscn` (+ `ui/dive_clock_meter.tscn`). It self-initializes from `GameState.start_run` → `run_started`, so no extra wiring beyond instancing.
- **Telemetry (opt-in):** can subscribe to `dive_clock_changed`/`dive_clock_timeout` via EventBus; throttle `dive_clock_changed` (~4 Hz or threshold-only) to avoid per-frame JSONL spam — noted in the spec, not implemented here (clock emits per-frame as designed).
- **Human/Director call:** the `max_light = 60` budget needs live playtesting (the M1 "is it fun?" dive-vs-extract tension). Recommend tuning here first.
- **Pause behavior:** the clock is `PAUSABLE`; whatever pause-menu/inventory UI lands later must set `get_tree().paused = true` (and run itself `WHEN_PAUSED`) to freeze the drain — no extra code in DiveClock.
