## What changed
Built the greybox pre-run **ConfigMenu** — a side-rail `Control` on the existing Main
Menu that surfaces **100% of `RunConfig`'s 32 `@export` knobs** and hands the
Director-built working config to the run. The menu owns ONE working `RunConfig` (a
`duplicate(true)` of the on-disk all-off default — the `.tres` is never mutated); each
control writes its bound field on change; a top summary line, per-section ON/OFF chip +
key-value summary, and per-row live SpinBox give three redundant readouts. `Reset to
baseline (all off)` reloads the default. `MainGame.start_new_run()` now stages the menu's
working config (ratified shape (a)) with a fallback to the on-disk default. Rows are
hand-authored per `RunConfig`'s field manifest, backed by a build-time **coverage
assertion** (`has_full_coverage()`) so no future knob can go unreachable.

## Design deviations
**none.** `RunConfig` has exactly the **32** fields the spec's §3.2 table lists (verified
against `data/run_config/run_config.gd`); all are bound. The §4 pseudocode is illustrative —
the implementation hand-authors the rows + keeps the coverage assertion (ratified §3.6).
Minor in-spec implementation choices: the seed_override row is a bare SpinBox (no slider —
it is an identity, not a magnitude); the slider+SpinBox pair makes the SpinBox the canonical
control so the type-exact escape hatch (§3.4a) is always the stored value.
