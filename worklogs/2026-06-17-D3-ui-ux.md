## What changed
Closed the Director-Addressed wave-3 deviation: D2's drop gesture removed the item
from the bag but never re-spawned it in the world because the `junk_dropped` emit
was missing. Wired it in `InventoryPanel._on_cell_drop_requested`: capture the
removed `JunkItem` from `RunInventory.remove_at()` (which returns it), then
`EventBus.junk_dropped.emit(dropped, drop_world_pos)` so C2's already-subscribed
`JunkSpawner` re-instantiates a grabbable `JunkPickup` via `spawn_one()`. Removal
happens first so the item is never both carried and on the ground (swap integrity).

## Design deviations
None — this task *closes* a deviation. Resolution of the open `drop_world_pos`
question (the only judgment call): the item drops at the **player's current world
position** ("I dropped it where I'm standing"). Because the panel is a `Control`
with no world transform and I am lane-restricted to `ui/inventory/` (cannot edit
`Player`, the spawner, `EventBus`, or `GameState`), I resolve the player from the
scene tree at drop time via a typed depth-first search for the `Player` class
(`_find_player`), reading its `global_position`. This needs no group registration
on the Player and no edits outside the UI lane. If no player is in the tree
(between dives / menus), it returns `Vector2.ZERO`; that is inert because C2's
spawner only acts when a band drop-container is registered (`_drop_container`), so
an out-of-dive drop re-spawns nothing rather than dropping junk at the world origin.
A stale/invalid index returns `null` from `remove_at` and we skip the emit (no
phantom drop). Recommend a future cleanup (post-M1, when the dive scene owns the
player) to add the Player to a `"player"` group and switch to
`get_first_node_in_group("player")` — cheaper than a tree walk — but that touches
the Player scene, which is out of this task's lane.
