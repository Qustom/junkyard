## Design deviations
- **Stale spec sketches corrected to as-built APIs (not a design change).** The G2
  spec's `LayoutGen.generate`/`a.tiles`, `Inventory.new(capacity)` + `{"id","value"}`
  dict items, `Economy.bank`/`Economy.sell`/`CURRENCY_RATE`, and
  `DeathDrop.resolve(carry)` with `int(carry*fraction)` do **not** exist. Tests were
  written against the shipped surface (`BandGenerator.generate`/`Band.fingerprint`,
  `JunkPlacer.plan`/`plan_fingerprint`, `RunInventory` + `JunkItem.base_sell_value`,
  `GameState.extract_and_end_run`/`sell_banked_junk`/`fail_run` + `RunRules`). M1_As_Built
  already wins per CLAUDE.md; no doc change needed.
- **`POCKET_FRACTION` open-Q recommendation (0.0) is stale; 0.20 is canonical.** The
  spec's open-question recommended losing everything on death; ratified decision #13
  set `pockets_fraction = 0.20` with whole-item HIGHEST_VALUE. The suite asserts the
  as-built 0.20 behavior. No deviation to log — the build already matches the ratified
  decision.
- **`test_jsonl_writer` deferred to integration.** The G2 spec lists a telemetry
  JsonlWriter suite, but the writer is built concurrently by G1 and is not on this
  branch. Skipped per the task brief; G1 ships its own lightweight writer check, and a
  full GdUnit4 writer suite can fold in after both branches merge (recommend adding
  `tests/telemetry/test_jsonl_writer.gd` as a post-merge follow-up — parseable rows +
  envelope-field presence).
- **`--ignoreHeadlessMode` is required** for the GdUnit4 CLI in CI (its default
  refuses headless to protect UI-input tests). Documented in `tools/run_gdunit.sh`
  and the CI step. Safe here because all G2 suites are pure-logic with no InputEvents.

## Pure-function-refactor costs surfaced (for future tasks)
- **No blocking refactor was needed.** The four systems under test are already
  test-friendly: B2/B3 are plain `RefCounted` with seed-injected pure entry points
  (`generate(seed,...)`, `plan(band,...)`), D1 `RunInventory` is a plain `RefCounted`,
  and the GdUnit4 harness loads autoloads so the E1/E3/F1 `GameState` methods are
  drivable as-is. The spec's anticipated "extract pure functions" budget did **not**
  materialize.
- **Minor seam noted, not acted on (G1 contention):** E1/E3/F1 logic lives on the
  `GameState` autoload rather than in a free function, so the economy suites mutate
  and restore global meta (`money`, `banked_junk`, `run_rules`) around each test. This
  is fine and isolated via `before_test`/`after_test` snapshots, but a future small
  refactor could lift the budget/sum math (`_resolve_pockets`, `_sum_values`,
  `run_haul_value`) into a static `EconomyMath` helper testable without the autoload.
  Not done here — `game_state.gd` is a G1 contention point this wave (brief: do not
  edit it). Recommend revisiting post-wave-5 if the autoload-snapshot pattern proves
  brittle.
