## Design deviations
Did NOT touch `event_bus.gd` or `game_state.gd` (the G2-contention files). No new
EventBus signals were added — the listener consumes only the existing locked
contract. Deviations from the **G1 spec sketch** (the As-Built doc explicitly says
it wins over the sketch), to be dispositioned by the Director at wave-5 close-out:

1. **No `Settings` autoload / no `telemetry_toggled` signal.** The sketch assumes
   `Settings.telemetry_enabled` + a `telemetry_toggled` signal on a Settings
   autoload. Instead, opt-in is a static `Settings` (RefCounted) helper over a
   `ConfigFile`, and the toggle is applied via `Telemetry.set_enabled()` called by
   the UI. Rationale: avoid adding an autoload mid-wave and avoid a signal that
   would (per the As-Built parallel-edit rule) need pre-declaring on `event_bus.gd`.
2. **Opt-in persisted in `user://settings.cfg`, NOT via the SaveManager meta
   schema.** The acceptance criterion says "persisted via SaveManager." Putting it
   in `meta.sav` would require a v2→v3 schema bump (+ migration step + binary
   fixture) and an edit to `game_state.gd`'s `to_meta_dict`/`from_meta_dict` — a
   contention file the brief says to avoid. A UI consent preference is arguably
   profile/process config rather than gameplay meta-state, so a dedicated
   ConfigFile is a reasonable home. **Flag for the Director:** if "via SaveManager"
   is a hard requirement, this becomes a follow-up task (schema bump + fixture).
3. **`run_started.data` logs `band_id` (+ seed), not `tier_label`.** The real
   `run_started(band_id, seed)` carries no tier label, and there is no tier/run-
   length-target field in M1 run state. `tier_label` (the 15/30/60-min bucket) is a
   G4-analysis-time classification derived from `run_ended.duration_s`, not
   something to log at start. Left out rather than fabricated.
4. **`run_id` is derived inside Telemetry from the seed**, not owned by GameState
   (the sketch's recommendation). The brief permits this when adding `run_id` to
   GameState risks conflict; since I was told not to touch `game_state.gd`, I
   derived `r_<hex(seed)>`. It is stable for the whole run (seed doesn't change
   mid-run) but is NOT unique if two runs reuse a seed — acceptable for M1 greybox
   analysis (rows also carry `session_id` + monotonic `t_ms`); revisit at G4 if
   collisions matter.
5. **Log path is `run_log.jsonl`** (G1 spec + As-Built), superseding the old
   `events.jsonl`. The QA playbook prose still says `events.jsonl` — a doc reapply
   for the Director at close-out, not a code change here.

All five are spec-sketch-vs-as-built reconciliations, none changes gameplay; also
appended to `design/DESIGN_DEVIATIONS.md`.
